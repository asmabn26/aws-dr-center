# Charte de travail du binôme

## 1. Membres

- Asma
- Ikram

## 2. Objectif

Organiser le travail du binôme afin que les deux membres participent à l’ensemble du projet et maîtrisent toutes les parties techniques.

## 3. Méthode pilote/copilote

Pour chaque tâche :

- une membre est désignée pilote ;
- l’autre membre est désignée copilote ou vérificatrice ;
- la pilote réalise la première version ;
- la copilote teste et relit le travail ;
- les rôles sont inversés régulièrement ;
- les décisions importantes sont prises ensemble.

## 4. Responsabilités de la pilote

La pilote doit :

- comprendre la tâche ;
- réaliser la configuration ou le document ;
- enregistrer les preuves ;
- documenter les étapes ;
- signaler les difficultés ;
- informer la copilote lorsque le travail est prêt.

## 5. Responsabilités de la copilote

La copilote doit :

- relire le document ;
- tester la configuration ;
- vérifier les résultats ;
- proposer les corrections ;
- valider le livrable ;
- être capable de reproduire la tâche.

## 6. Organisation quotidienne

Chaque journée comprend :

1. une réunion de 10 à 15 minutes ;
2. la définition des objectifs du jour ;
3. la réalisation des tâches ;
4. une validation croisée ;
5. la mise à jour du tableau de suivi ;
6. un commit Git ;
7. la mise à jour du journal.

## 7. Règles Git

- travailler sur une branche dédiée ;
- ne pas pousser directement sur `main` ;
- créer une Pull Request ;
- faire relire la Pull Request par l’autre membre ;
- utiliser des messages de commit clairs ;
- ne jamais publier de secret.

## 8. Gestion des documents

GitHub est utilisé pour :

- le code ;
- les scripts ;
- les fichiers Terraform ;
- les documents Markdown ;
- les petites captures utiles.

Google Drive est utilisé pour :

- les fichiers PDF ;
- le rapport ;
- les présentations ;
- les vidéos ;
- les captures volumineuses ;
- les documents bureautiques.

## 9. Gestion des coûts AWS

Après chaque séance :

- vérifier les instances EC2 ;
- vérifier les volumes EBS ;
- vérifier RDS ;
- vérifier les snapshots ;
- vérifier les points de récupération ;
- supprimer les ressources temporaires ;
- consulter le tableau de facturation ;
- noter le coût dans le journal.

## 10. Gestion des blocages

Lorsqu’un problème empêche l’avancement :

- le statut passe à `Bloqué` ;
- le problème est décrit ;
- sa cause probable est notée ;
- une action corrective est proposée ;
- une personne responsable est désignée ;
- une date de nouvelle vérification est définie.

## 11. Validation d’une tâche

Une tâche est validée seulement lorsque :

- le résultat est fonctionnel ;
- le livrable est complet ;
- la copilote l’a vérifié ;
- une preuve est disponible ;
- la documentation est à jour ;
- les deux membres savent l’expliquer.
